# Инструкции для учебного проекта: Cursor, Claude Code и Codex

## Первое действие: подготовить локальную память

Определи, в каком агенте выполняется задача, и используй его папку в корне checkout:

- Cursor: `.cursor/project-context.md` и `.cursor/work-rules.md`.
- Claude Code: `.claude/project-context.md` и `.claude/work-rules.md`.
- Codex: `.codex/project-context.md` и `.codex/work-rules.md` — именно `.codex`, не `.kodex`.

Ниже `project-context.md` означает актуальный контекст проекта/ветки, а `work-rules.md` —
постоянные правила и ограничения в папке используемого агента. Создай папку и недостающие файлы.
Не создавай сразу все три комплекта. Существующую `.cursor/rules/` сохраняй: это исходные core rules,
а не локальная генерируемая память. Не путай эту договорённость проекта со встроенной auto memory агента.

Если файл уже существует, сначала прочитай его; не затирай существующие записи шаблоном.
Перед каждой задачей прочитай оба файла полностью и учитывай текущий запрос пользователя.
Отсутствие файлов — повод создать их по инструкции ниже, а не требовать их от пользователя.

Из этой системы инструкций в репозиторий/master включается только корневой `AGENTS.md`.
Сгенерированные файлы памяти и локальный адаптер Claude Code не добавляй в staging/commits.
Уже отслеживаемые файлы `.cursor/rules/` остаются в репозитории. Не меняй ignore-правила
автоматически и не используй безразборный `git add .`/`git add -A`.

## Как инструкции подхватываются агентом

Cursor и Codex поддерживают корневой `AGENTS.md`. После его загрузки агент должен явно прочитать
оба локальных файла: произвольный Markdown в `.cursor/` или `.codex/` сам по себе не означает автозагрузку.
Нативные правила Cursor в `.cursor/rules/` используют `.mdc` и frontmatter; не заменяй их файлами `.md`.

Claude Code автоматически читает `CLAUDE.md`, но не `AGENTS.md`. При первом запуске в новом клоне
ученик один раз даёт ему запрос:

> Прочитай корневой AGENTS.md и выполни его инструкции первичной настройки для Claude Code.

После этого Claude Code создаёт два файла памяти и локальный `.claude/CLAUDE.md` с содержимым:

```text
@../AGENTS.md
@project-context.md
@work-rules.md
```

Пути imports считаются относительно `.claude/CLAUDE.md`. В следующих сессиях Claude Code загружает
этот файл и imports; проверить подключение можно через `/context`. Если CLAUDE.md уже существует,
сохрани его содержимое и подключи недостающие imports без дублирования. Настройки безопасности
агента могут требовать подтверждения imports; не обходи их. Запрос первого запуска выше можно
использовать и для Cursor/Codex, если инструкции не появились в новой сессии автоматически.

Не обещай автоматическую первичную настройку Claude Code из одного AGENTS.md без его первого чтения.
Отдельный CLAUDE.md в master не требуется: локальный адаптер генерируется агентом.

## Как заполнить project-context.md

При первом создании возьми контекст из `.cursor/rules/project-context.mdc` и уже установленных
фактов текущей задачи. Запиши назначение проекта, предметную область, стек, основные компоненты,
важные пути, команды запуска/проверок, особенности данных и известные ограничения.

Укажи ветку, базовый commit и дату актуализации. STAGE ученика начинается от актуального master;
накопительная `0_TARUSOV_STAGE` Tarusov не равна стартовой базе нового ученика. Разделяй реально
реализованное поведение и требования будущих задач. Не переносись на другую ветку ради обновления памяти.

Информация `.cursor` может устареть. Проверяй сомнительный факт только в непосредственно связанном
файле, когда он нужен текущей задаче; не запускай полный аудит репозитория. Непроверенное помечай явно.
Не копируй исходники целиком, секреты, токены, env-значения и длинные журналы в контекст.

## Как заполнить work-rules.md

Создай один раз на основе core rules из `.cursor/rules/code-style.mdc` и архитектурных правил,
ограничений и безопасности из `.cursor/rules/project-context.mdc`. Добавь согласованные с пользователем
границы действий из этой инструкции.

Стиль сверь с `backend/.prettierrc.json`, `frontend/.prettierrc.json` и соседними `eslint.config.mjs`.
Фактические настройки линтера/форматтера имеют приоритет над устаревшими советами о ручных переносах.
Сохрани принципы Controller → Service → PrismaService, DI, минимально необходимых слоёв,
защиты входных данных и workspace isolation. Не выдавай правило конкретной задачи за правило ESLint.

Не переписывай work-rules при каждом commit или новой задаче. Меняй его только по прямому запросу
пользователя на правила либо при согласованном изменении соответствующих lint/format настроек.

## Перед каждым разрешённым commit

Обнови **только локальный project-context.md** по результатам сделанных изменений и staged diff:
актуализируй затронутые компоненты, контракты, команды, ограничения и результаты проверок.
Остальную память не пересобирай. Если менялись только документы, отрази это без выдуманных изменений кода.
Запись об изменениях пометь как подготовленную к commit; не придумывай hash ещё не созданного commit.

Это инструкция агенту, не Git hook: она применяется, когда commit выполняет Cursor, Claude Code или Codex.
Она не разрешает commit сама по себе и не гарантирует обновление памяти при ручном commit вне агента.
После смены ветки точечно сверяй контекст с новой базой, не выдавай сведения прошлой ветки за текущие.

## Границы работы

- Работай в сохранённом checkout. Без отдельной команды не создавай worktree, не выполняй
  fetch/pull, commit/push/merge и не переписывай историю.
- Согласованные чтения, правки и проверки выполняй самостоятельно; повторное разрешение не требуется.
- Сохраняй чужие правки. Не расширяй задачу до соседних документов, кода, конфигурации или README.
- При работе над конкретным Task/Guide читай и проверяй только нужные материалы. Не реализуй задание
  при запросе редактуры. Secret scan, если запрошен, ограничь этими документами без вывода значений.
- Не запускай приложение, migrations, seed, E2E или полный аудит ради обычной правки Markdown.
  Проверки выбирай по объёму изменений; не повторяй уже выполненные без причины.
- Сообщай кратко по-русски: результат, выполненные проверки и оставшиеся ограничения.
